# Rules Reference

Detailed tables, templates, and examples for each `resume-positioning` rule. The core SKILL.md references this file for heavy content.

> **All examples below are illustrative.** They use a sample candidate moving from managed IT services (MSP) into SaaS so the patterns are concrete. Put your own translations, aliases, and metrics in `strategy/positioning.md`; that file always takes precedence over this one.

## Rule 2: Scope Preamble Template (Per Role)

Each experience entry opens with a 1-2 sentence scope preamble before the bullet list. This replaces the standalone Leadership Scope block — scope is embedded per-role so each entry is self-contained and the leadership signal is impossible to miss.

**Template:**
```
[Scope preamble: 1-2 sentences stating team size, org functions, revenue/client scope, and accountability.]
```

**Examples by mode:**

*People Leadership:*
> Led a 20-person cross-functional organization across Support, Implementation, and Client Success for an $8M ARR managed services portfolio serving 40 clients, accountable for team performance, client retention, and service delivery standards.

*Operations/Systems:*
> Owned the end-to-end service operations infrastructure across 40 client accounts and 1,500+ end users, responsible for process design, tooling, and the KPI frameworks that surfaced operational health to senior leadership.

*Hybrid:*
> Managed a 6-person team across Account Management and Service Desk functions while owning the operational systems (reporting dashboards, SLA frameworks, problem management) that the team ran on.

*Consulting/Founder:*
> Built and led a 2-person contract team to deliver small-business advisory services and a content-driven lead generation engine across a $50K annual revenue client base.

**Framing rules:**
- Always state headcount explicitly ("6 direct reports" not "a small team")
- Include org functions spanned, not just the team name
- Include revenue or portfolio scope when it exists
- State what you were accountable *for*, not just what you *did*

## Rule 3: Technology Platform Alias Map

Include both the **actual platform** and the **well-known equivalent** for ATS matching. Example format:

```
**CRM & CS Platforms**: ConnectWise PSA (ServiceNow-class service management)
**Knowledge Management**: IT Glue (comparable to Confluence)
**Workflow Automation**: Power Automate (comparable to Zapier)
**Data & Reporting**: NicheBI (comparable to Looker, Tableau)
```

**Mode-adaptive phrasing:** In Operations-mode resumes, replace "comparable to" with class-equivalency language: "NicheBI (Looker/Tableau-class)." Only reference platforms the candidate has actually used, and never list a well-known platform as if it were used when it was only the comparison class.

## Rule 5: Professional Title Selection

### Use the Exact Job Title From the Posting

Place the **exact job title from the target posting** under the candidate's name. ATS systems parse this field heavily — exact matching is a higher-ROI move than adaptation. This is distinct from body text, where verbatim repetition reads as keyword stuffing; the title field is explicitly scanned for role-match signals.

**Examples (exact match):**

| Target Posting Title | Resume Title Field |
|---|---|
| Director, Customer Operations | Director, Customer Operations |
| Services Delivery Manager | Services Delivery Manager |
| Implementation Lead (Enterprise) | Implementation Lead (Enterprise) |
| Manager, Support Operations | Manager, Support Operations |

### Selection Process

1. **Find the exact job title** in the posting (usually in the page header or first paragraph)
2. **Copy it verbatim** — including commas, parentheses, and capitalization
3. **If the posting uses two interchangeable titles**, use the more senior one
4. **If the title contains a department code or requisition number**, strip those — keep only the human-readable title
